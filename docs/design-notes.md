## 共通方針（全スキル）

- スクリプトで代わりにできることはスクリプトにする（差分からの関数抽出、docblock がない関数の列挙、検査など）。

## プラグイン: `code-comments`

### 構成案

```
plugins/code-comments/
├── .claude-plugin/plugin.json
├── hooks/hooks.json    # SessionStart: rules を注入 / PostToolUse(Edit|Write): 検出スクリプト
├── rules/comments.md   # 注入する原則（短く保つ。毎セッション入るため）
├── scripts/            # 検出スクリプト（hook とスキルで共用）
└── skills/docblock/
    ├── SKILL.md
    └── references/
        ├── style-ja.md # 日本語の文体・述語の語彙表・禁止語
        ├── php.md      # PHPDoc の記法、型宣言との重複の扱い
        └── js-ts.md    # JSDoc / TSDoc、JS と TS の差分
```

- CLAUDE.md はプラグインに入れられないので、原則は SessionStart hook でコンテキストに注入する。
- 原則はコードの修正中（レビュー対応など）にも効かせたいので、スキルではなく hook で常時有効にする。

### 対象

- doc は日本語で書く。
- 言語は PHP・JS（会社）と TS（プライベート）。スキルは 1 つにまとめ、言語ごとの違いは references とスクリプトで分ける。
  - TS: シグネチャに型があるので、JSDoc に型を重ねて書かない。
  - JS: JSDoc の型を書く。
  - PHP: 型宣言がある場合の `@param` の型の扱いは `php.md` で決める。
- 会社の規約はスキルに含めない。リポジトリに規約ファイル（例: `.docblock.md`）があれば優先して読む。

### 原則と書式

- 注入する本文は `plugins/code-comments/rules/comments.md` にある。
- 文体は常体。summary は 1 文で、文末に「。」をつけない。

### 抑制したいもの

1. 一般的でない語彙（動詞・述語）
2. 変更経緯を書くこと（「当初 A だったが〜のため B に変更」）。doc だけでなくコメントも対象。
3. コードをそのまま言い換えるだけのコメント（`// ユーザーを取得する`）
4. 区切り線や見出しだけのコメント

### 語彙の対策

- 述語の語彙表: 返す / 生成する / 判定する / 設定する / 追加する / 削除する / 変換する
- 禁止・置き換え
  - 「〜を取得する」→「〜を返す」（取得元があるときだけ「取得する」を使う）
  - 「処理する」「実施する」「担う」「行う」は禁止（内容がわからないため）
  - 「〜するための関数です」は禁止（冗長）
  - 「〜をキューに積む」→「〜をキューに追加する」（「積む」はスタックを連想させる。レビューで指摘された実例）
  - 「触れる」→「使う」「含む」など具体的な動詞（間接的でわかりにくい）
  - 文末の「〜している」→「〜する」（時系列を感じさせる。文の途中で状態を表す「〜しているため」はよい）
- 既存の docblock の文末と述語をスクリプトで集計し、頻度表を AI に渡す（基準をこのリポジトリの実際の語彙にする）。

### スクリプトでの検出（差分で追加された行だけを対象にする）

- docblock がない関数（宣言行か、そのすぐ上の行が追加されたもの）
- 直後に空行がある docblock（ファイル先頭の docblock は除く）
- `@param` の名前が関数の引数にない docblock（関数の間に別の関数を差し込み、docblock がずれたもの）
- 関数名の接頭辞（`vocabulary.json` の `prefixes`）から推定した述語と、summary の述語が違う docblock
- docblock は変更されていないのに、宣言行が変わった関数。上の 2 つで判定できないずれと書き直し漏れを、関数名と summary を見比べて AI に確認させる
- summary 行の文末・述語が語彙表にないもの（述語は関数の docblock だけ）
- summary・詳細・タグのかたまりの間に空行が 1 行ないもの（2 行以上も含む）
- 経緯語（`vocabulary.json` の `history`）。「今回」は「今回の修正」「今回から」、「対応」は「対応した」「対応済み」のように、変更の出来事を指すときだけ対象にする
- コメントアウトされたコード（ヒューリスティック）
- チケット番号のない TODO
- 誤検出はあってよい。AI に確認させて直させる。

### スクリプトの実装

- Node で統一し、ホストだけで動かす（会社はホストに Node、VM に PHP。PHP の構文確認は SSH 経由）。
- 今は依存なしで、関数とコメントを行単位のパターンマッチで抽出している（`scripts/lib/`）。
  - 修飾子のない JS のメソッドは、シグネチャが 1 行で `{` で終わるものだけを検出する。関数の中の arrow 関数は対象外。
  - 語彙表・禁止語・置き換え・経緯語は `vocabulary.json` に置き、スクリプトが読む。
- 精度が足りなければ、パーサーに置き換える。
  - JS/TS: `typescript` の compiler API
  - PHP: npm の `php-parser`（glayzzle）。SSH 経由の `php -r` は、hook が編集のたびに動くため使わない。
  - プラグインのインストールでは `npm install` が実行されないため、依存の配り方（バンドルしてコミットするなど）を先に決める。

## プラグイン: `backlog`（会社用）

- `/backlog:assign [課題キー]` で起動する。入口の判定と git の操作は `skills/assign/scripts/assign.js` が行い、AI は質問・整形・要約だけを行う。
- 会社固有の値（他リポジトリの検索先）は `~/.claude/backlog.json` に置く。このリポジトリは公開のため。

### 課題ディレクトリの構成

```
.claude/PP-1234/
├── 00_サマリー/              今の状態。書き換えてよい。Backlog の親課題・子課題と PR 本文の元
│   ├── 要求.md                Backlog の親課題の「## 要求」から取得する
│   ├── 調査および要件定義.md
│   ├── 実装.md
│   ├── PR本文.md
│   ├── ...
│   ├── 進捗.md                今のまま
│   └── やること.md            今のまま
├── 01_<ユニットの名前>/        閉じたユニットは書き換え禁止
│   └── 要求.md ...
└── 02_<ユニットの名前>/        最新のユニットだけ書き換えられる
```

- ステージごとのファイル: 要求 / 調査および要件定義 / 実装 / PR本文 / AIレビュー / 第三者テスト / 開発者確認 / リリース後の動作確認
  - Backlog との対応: 要求は親課題。調査および要件定義・実装・第三者テスト・開発者確認・リリース後の動作確認は子課題
  - ファイル名に番号は付けない。並び順はスクリプトと SKILL.md の一覧で決める
- ユニット: 1 つの要求に対する作業のまとまり。例: バグの修正で 1 つ、その実装の AI レビューで問題が見つかったら、その修正でもう 1 つ
  - ユニットとサマリーのどちらに、どのステージのファイルを置くかは決めない。どれでも使えるようにして、使いながら決める
  - ファイルは必要になったときに作る。使わないステージのファイルを作ったときは「該当なし」と書く
  - 次のユニットを作った時点で、前のユニットを閉じる（書き換え禁止）。ユニットの作成はスクリプトで行い、番号の付け方と閉じるタイミングをそろえる
- サマリー: ユニットを閉じるたびに、AI がユニットの内容をサマリーに反映する
  - 反映漏れはスクリプトで検出する（サマリーが最新のユニットより古いか、など）
- 要求の取得
  - Backlog の親課題には、ローカルとは別の「## 進捗」もあるため、「## 要求」セクションだけを取る
  - 今の課題は別の見出しを使っている（主に「## 要件」）。「## 要求」がなければ、どのセクションを取るかを確認する
  - 親課題は Backlog MCP サーバーで取得する（取得にだけ使える）。手動のコピペはやめる
  - 「## 要求」の取り出しはスクリプトで行う。なければ見出しの一覧を返し、それを選択肢にして聞く
  - 親課題は Backlog 側で常に更新されるため、全文をローカルに残さない（`親課題.md` は廃止）。`00_サマリー/要求.md` には「## 要求」だけを置く
- Backlog への書き込み
  - サマリーの各ファイルは、Backlog API で書き込む（API キーの利用は許可されている。MCP は書き込みに使えない）
  - API キーとスペースの URL は公開リポジトリに置かない。環境変数か `~/.claude/backlog.json` から読む

### 実装済み

- `assign.js`: `status`（新旧の構成を判定）、`requirement`（「## 要求」の取り出し）、`unit`（ユニットの作成）、`file`（ステージのファイルの作成）
- 閉じたユニットへの Edit / Write を拒否する PreToolUse hook（`hooks/hooks.json` → `guard-closed-unit.js`）。Bash での書き換えは防げない
- 古い構成（`親課題.md` と `ver.X`）の課題も読める。移行は頼まれたときだけ
